# Contributing

## Scope

Contributions should improve session isolation, reliability, observability, security, performance, maintainability, or documentation.

## Workflow

1. Read AGENTS.md.
2. Create a branch.
3. Reproduce or measure the problem.
4. Implement the smallest safe change.
5. Add or update tests.
6. Run concurrency regression.
7. Compare benchmarks when performance-related.
8. Update documentation.
9. Update CHANGELOG.md when user-visible or operational behavior changes.
10. Open a PR.

## Pull request expectations

A PR should explain:

- problem;
- root cause and evidence;
- change;
- risk;
- tests;
- concurrency impact;
- auth and security impact;
- telemetry impact;
- rollback.

## Architecture changes

Add an ADR for changes to:

- session ownership;
- auth model;
- broker lifecycle;
- storage;
- browser engine;
- telemetry backend;
- public MCP semantics.

## Secrets

Do not attach production diagnostic files unless they are generated by the sanitized diagnostics workflow and reviewed.

## Performance changes

Provide before and after numbers, not subjective claims.

## Compatibility

During the side-by-side phase, every substantial runtime change should consider a regression check proving V1 remains unaffected.
