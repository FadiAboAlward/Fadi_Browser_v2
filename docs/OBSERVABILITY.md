# Observability

## Purpose

The system must be diagnosable after days or weeks of real use.

Observability should answer what happened without recording private browsing content.

It must also make V1-class operability problems visible: queue dead-ends, ownership ambiguity, browser window confusion, auth restore failures, and unnecessary public lease-handle coupling.

## Storage targets

### SQLite

Durable structured event and metric store.

### Rotating JSONL

Human and AI-readable local diagnostic stream.

Default target retention: 30 days.

No cloud telemetry by default.

## Browser identity and visibility

For headful sessions, diagnostics should make it possible to distinguish the correct visible browser, a minimized/off-screen browser, a hidden browser, duplicate browser launch, and wrong profile attachment.

Use safe operational identifiers only; never expose profile contents.

## Permission-friction regression signal

The broker cannot always see UI approval prompts generated by the host platform before tool invocation.

Therefore QA, not only runtime telemetry, must include an explicit authorized-flow permission test proving that normal lease lifecycle operations do not require a credential-like public argument that triggers unnecessary approval.

## Privacy

Do not log passwords, OTPs, cookies, authorization headers, token contents, full private URL query strings, DOM/page text, screenshots by default, or sensitive request/response bodies.

Prefer origin or hostname.

## Report command

Support at least 1, 7, 14, and 30 day windows.

Include version comparison where enough data exists.

## Diagnostic bundle

Generate a sanitized archive containing versions, process/service state, port/health results, safe config, recent structured errors, aggregate metrics, latest QA/test outputs, queue statistics, browser/window identity diagnostics, and relevant OS/resource metadata.

It must exclude auth state.

## Performance regression

A change is a performance regression when measured behavior materially worsens versus the versioned baseline under comparable workload.

Never rely only on subjective reports that the system feels slower.
